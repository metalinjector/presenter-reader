# Постановка задачи: извлечение слайдов презентации из записи вебинара

## 1. Назначение

Нужна универсальная программа на Python, которая анализирует видео вебинара и:

- находит в кадре область, где ведущий показывает презентацию;
- определяет, сколько слайдов было показано за вебинар;
- сохраняет **по одному скриншоту на каждый показанный слайд**, без повторов.

## 2. Исходная ситуация

1. Во время вебинара ведущий показывает на экране презентацию: слайды, таблицы, схемы, видеоролики и т. п.
2. Пока ведущий объясняет слайд, тот висит на экране без изменений долго: обычно 5–10 минут, иногда 25 минут и больше.
3. Вебинар может идти несколько часов (например, 3 часа). За это время может смениться 10–15 слайдов, а в общем случае — сколько угодно.
4. Почти всегда в кадре есть видео ведущего в прямом эфире (веб-камера). Оно может быть справа, слева, в углу или в любом другом месте экрана. Это видео постоянно двигается, то есть **не статично**.
5. При этом в кадре всегда есть область, где картинка **статична**: она не дёргается и не меняется. Именно в этой области сменяют друг друга слайды презентации.

## 3. Что должна делать программа

### 3.1. Найти область презентации

- Автоматически найти участок кадра, где изображение подолгу остаётся неизменным.
- Эта область **обязательно прямоугольная**. Программа выделяет её прямоугольным маркером для внутреннего использования.
- Видео ведущего и другие постоянно меняющиеся элементы не должны попадать в анализ и влиять на результат.
- Где находятся камера и презентация, заранее неизвестно. Программа определяет это сама для каждого видео, без ручной настройки.

### 3.2. Отследить смену слайдов

- Внутри найденного прямоугольника фиксировать моменты, когда одна статичная картинка сменяется другой.
- Новый слайд — это новое изображение, которое после смены снова остаётся статичным.
- Кадры перехода между слайдами (анимация смены, кратковременные изменения) слайдами не считаются.

### 3.3. Выдать результат

- Количество показанных слайдов.
- Ровно столько скриншотов, сколько было слайдов: по одному на каждый, обрезанному по найденной области.
- Скриншоты разовые и уникальные: один и тот же слайд сохраняется один раз.

## 4. Требования к качеству

| Требование | Что это значит |
|---|---|
| Универсальность | Работает с записями разных платформ (Zoom, Teams, МТС Линк / Webinar.ru, YouTube и т. п.) и с любым расположением камеры и презентации. |
| Скорость | Многочасовая запись обрабатывается намного быстрее, чем длится сама. Анализировать полностью каждый кадр не нужно. |
| Точность | Слайды не пропускаются. Лишних скриншотов нет: ни дублей, ни кадров перехода, ни кадров с ведущим. |

## 5. Помехи, которые нужно учитывать

Эти пункты прямо в задаче не названы, но без них нельзя добиться точности. Каждый пункт требует подтверждения.

1. **Курсор мыши или указка** движется по слайду. Это не смена слайда.
2. **Артефакты сжатия видео**: шум, «дрожание» мелких деталей. Это не смена слайда.
3. **Плавные переходы** между слайдами (затухание, сдвиг). Промежуточные кадры не сохраняются.
4. **Повторный показ** слайда, когда ведущий вернулся назад. Это не новый слайд, и повторный скриншот не нужен.
5. **Пошаговая анимация** на слайде, когда пункты появляются по одному. Предлагается считать это одним слайдом и сохранять его итоговое, самое полное состояние.
6. **Периоды без презентации**: ведущий на весь экран, вопросы и ответы, заставки. Скриншоты в эти периоды не создаются.
7. **Смена раскладки экрана** по ходу вебинара: камера переехала, презентацию свернули и снова развернули.

## 6. Предлагаемые дополнительные возможности (по желанию)

- Отчёт с тайм-кодами показа каждого слайда (CSV / JSON / HTML).
- Сборка всех слайдов в один PDF-файл.
- Ручное задание области презентации, если автоопределение ошиблось.
- Отладочное изображение кадра с нарисованным найденным прямоугольником.

## 7. Критерии приёмки

1. На тестовых записях число найденных слайдов совпадает с фактическим числом показанных слайдов.
2. Найденный прямоугольник совпадает с областью презентации и не включает видео ведущего.
3. Среди скриншотов нет дублей, кадров перехода и кадров с ведущим.
4. Каждый скриншот читаем: текст слайда различим, нет следов соседнего слайда.
5. Запись длиной около 3 часов обрабатывается за минуты, а не за часы.

## 8. Открытые вопросы

1. Источник видео: только готовые записи или ещё и захват экрана в реальном времени, во время живого вебинара?
2. Анимацию на слайде сохранять одним итоговым скриншотом или каждый шаг отдельно?
3. Если слайд показали повторно, сохранять его ещё раз или только отметить время повторного показа?
4. Какое минимальное время показа считать слайдом (например, не меньше 3 секунд)?
5. Скриншоты сохранять в PNG или JPG? Обрезать по области презентации или дополнительно сохранять полный кадр?
