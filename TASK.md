# Постановка задачи: извлечение слайдов презентации из записи вебинара

## 1. Назначение

Нужна универсальная программа на Python, которая анализирует **готовую видеозапись** вебинара и:

- находит в кадре область, где ведущий показывает презентацию;
- определяет, сколько картинок (слайдов) было показано в этой области за вебинар;
- сохраняет **по одному скриншоту на каждую показанную картинку** в формате PNG.

## 2. Исходная ситуация

1. Во время вебинара ведущий показывает на экране презентацию: слайды, таблицы, схемы и т. п.
2. Пока ведущий объясняет слайд, тот висит на экране без изменений, обычно 5–10 минут, иногда 25 минут и больше. Но слайд может быть показан и совсем недолго.
3. Вебинар может идти несколько часов (например, 3 часа). За это время может смениться 10–15 слайдов, а в общем случае — сколько угодно.
4. Почти всегда в кадре есть видео ведущего в прямом эфире (веб-камера). Оно может быть справа, слева, в углу или в любом другом месте экрана. Это видео постоянно двигается, то есть **не статично**.
5. При этом в кадре всегда есть область, где картинка **статична**: она не дёргается и не меняется, в отличие от видео ведущего. Именно в этой области сменяют друг друга слайды презентации.
6. Слайды, как правило, статичны: один слайд — одна неподвижная картинка.

## 3. Что должна делать программа

### 3.1. Найти область презентации

- Автоматически найти участок кадра, где изображение остаётся неизменным, пока видео ведущего постоянно меняется.
- Эта область **обязательно прямоугольная**. Программа выделяет её прямоугольным маркером для внутреннего использования.
- Видео ведущего и другие постоянно меняющиеся элементы не должны попадать в анализ и влиять на результат.
- Где находятся камера и презентация, заранее неизвестно. Программа определяет это сама для каждого видео, без ручной настройки.

### 3.2. Найти все показанные картинки

- Внутри найденного прямоугольника фиксировать каждый момент, когда одна неподвижная картинка сменяется другой.
- Слайдом считается **любая** картинка, которая остановилась в области презентации. Минимального времени показа нет, количество картинок не ограничено.
- Слайдами не считаются только промежуточные кадры перехода: анимация смены слайда, затухание, сдвиг. Они не бывают неподвижными.
- Если слайд собирается по шагам (пункты появляются по одному), сохраняется **один кадр** — итоговое, самое полное состояние.

### 3.3. Повторный показ слайда

- Если ведущий вернулся к уже показанному слайду, скриншот **сохраняется ещё раз**.
- В имя такого файла добавляется пометка: на какой из ранее сохранённых слайдов он похож и **процент сходства**.

### 3.4. Сохранение скриншотов

- Формат — **PNG**.
- Скриншот обрезается по области презентации. Если размер этой области по ходу вебинара менялся, обрезка идёт по **самому большому** прямоугольнику показа презентации.
- В имени файла указаны порядковый номер слайда и время его показа в записи.
- Программа сообщает общее количество сохранённых слайдов.

## 4. Требования к качеству

| Требование | Что это значит |
|---|---|
| Универсальность | Работает с записями разных платформ (Zoom, Teams, МТС Линк / Webinar.ru, YouTube и т. п.) и с любым расположением камеры и презентации. |
| Скорость | Многочасовая запись обрабатывается намного быстрее, чем длится сама. Анализировать полностью каждый кадр не нужно. |
| Точность | Не пропускать ни одну показанную картинку. Не сохранять кадры перехода, кадры с ведущим и лишние копии одной и той же картинки. |

## 5. Помехи, которые нужно учитывать

1. **Курсор мыши или указка** движется по слайду. Это не смена слайда.
2. **Артефакты сжатия видео**: шум, «дрожание» мелких деталей. Это не смена слайда.
3. **Плавные переходы** между слайдами. Промежуточные кадры не сохраняются.
4. **Периоды без презентации**: ведущий на весь экран, вопросы и ответы, заставки. Скриншоты в эти периоды не создаются.
5. **Смена раскладки экрана** по ходу вебинара: камера переехала, презентацию свернули и снова развернули, изменился размер области показа.

## 6. Результат работы программы

- Папка со скриншотами в формате PNG, по одному на каждую показанную картинку. Имя файла содержит номер и время показа, а для повторов — номер похожего слайда и процент сходства.
- Общее количество слайдов.
- Дополнительно: отчёт с тайм-кодами показа каждого слайда и изображение кадра с нарисованным найденным прямоугольником, чтобы проверить, правильно ли найдена область.

## 7. Критерии приёмки

1. На тестовых записях число скриншотов совпадает с числом картинок, которые действительно показывались в области презентации, включая повторные показы.
2. Найденный прямоугольник совпадает с самой большой областью показа презентации и не включает видео ведущего.
3. Среди скриншотов нет кадров перехода и кадров с ведущим.
4. Повторно показанные слайды сохранены ещё раз, и в имени файла указан процент сходства с ранее сохранённым слайдом.
5. Каждый скриншот читаем: текст слайда различим, нет следов соседнего слайда.
6. Запись длиной около 3 часов обрабатывается за минуты, а не за часы.
